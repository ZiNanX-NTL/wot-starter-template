# 路由登录拦截

### Requirement: 登录策略与页面级配置

系统必须支持黑名单和白名单两种登录策略，并允许页面通过 `definePage` 声明 `auth` 元信息覆盖默认策略。

#### Scenario: 黑名单模式访问普通页面

- WHEN 全局策略为黑名单模式且目标页面未命中黑名单
- THEN 无论当前登录状态如何都允许导航

#### Scenario: 白名单模式访问未列入白名单的页面

- WHEN 全局策略为白名单模式且目标页面未列入白名单
- THEN 未登录用户被视为需要登录并拦截，已登录用户允许导航

#### Scenario: 页面声明需要登录

- WHEN 页面通过 `definePage` 声明 `auth: true`
- THEN 该页面在任意策略下都被标记为需要登录

### Requirement: 登录态判断

系统必须依据 Token 存在且未超过过期时间判断已登录状态；缺失、格式无效或过期 Token 均视为未登录，并清理失效 Token。

#### Scenario: Token 有效

- WHEN 存在未过期 Token
- THEN 路由守卫将当前状态判定为已登录

#### Scenario: Token 过期

- WHEN Token 的过期时间早于当前时间
- THEN 路由守卫清理 Token 并按未登录流程继续处理

### Requirement: 路由拦截器注册与判断顺序

系统必须注册全局前置路由拦截器，并按以下顺序执行：微信小程序特殊处理、登录态检查、登录回跳地址构建、策略判定。

#### Scenario: 微信小程序启动场景

- WHEN 在微信小程序端首次启动且页面信息尚未完成初始化
- THEN 守卫等待/兼容页面信息，不调用浏览器专属 API，并继续执行统一登录态判断

#### Scenario: 已登录访问登录页

- WHEN 当前用户已登录且目标页面是登录页
- THEN 优先跳转有效 `redirect` 地址，否则跳转首页

#### Scenario: 已登录访问普通页面

- WHEN 当前用户已登录且目标页面不是登录页
- THEN 直接放行，不重复跳转登录页

### Requirement: 未登录拦截与回跳

未登录访问需要登录的页面时，系统必须构建包含路径、查询参数和 hash（如有）的 URL 编码回跳地址，并跳转到登录页。

#### Scenario: 未登录访问受保护页面

- WHEN 当前用户未登录且目标页面需要登录
- THEN 跳转登录页并附带 `redirect` 参数，原始地址可被无损恢复

#### Scenario: 未登录访问公共页面

- WHEN 当前用户未登录且目标页面不需要登录
- THEN 允许导航，不附加多余重定向

### Requirement: 微信小程序兼容

微信小程序端必须使用 uni-app 路由与存储能力完成拦截和回跳，避免依赖 `window`、`location`、History API；登录页回跳失败时应降级到首页。

#### Scenario: 小程序回跳地址不可用

- WHEN 微信小程序无法恢复保存的回跳页面
- THEN 清理无效回跳并导航到首页，避免页面栈循环
